# 데이터 출처 정리와 라이선스 결정

2026-09-18 작성. 목적은 `configs/data/preparation.json`의 **`allowed_licenses`를 채울 수 있는 상태로 만드는 것**이다. 이 배열이 비어 있으면 `data_pipeline/prepare.py`가 실행 자체를 거부하므로, 여기서 정리한 항목을 확인하기 전에는 데이터 파이프라인을 시작할 수 없다.

## 0. 이 문서의 한계

**아래 표의 라이선스는 후보를 좁히기 위한 참고이며 법적 확인이 아니다.** 각 기관의 이용약관은 개정된다. 실제로 데이터를 받을 때 해당 사이트의 현재 약관을 직접 읽고, 확인한 날짜와 약관 버전을 §6 기록표에 남겨야 한다.

`prepare.py`는 `license` 문자열이 `allowed_licenses`에 있는지만 본다. **허용 목록에 이름을 적는 행위가 이용 권리를 만들지는 않는다.** 이 점은 [데이터 준비 문서](data-readiness.md)에도 명시되어 있다.

## 1. 라이선스 식별자 체계

`prepare.py`는 문자열 완전 일치로 검사하므로 식별자를 자유롭게 쓰면 안 된다. 아래 어휘만 사용한다.

| 식별자 | 의미 | 사전학습 사용 |
|---|---|---|
| `own-work` | 우리가 직접 작성한 문서·예시 | 가능 |
| `public-domain` | 저작권 보호기간 만료 또는 권리 포기 | 가능 |
| `cc-by-4.0` | 출처표시 | 가능 |
| `cc-by-sa-4.0` | 출처표시 + 동일조건변경허락 | 가능 |
| `kogl-type-1` | 공공누리 제1유형 (출처표시, 상업·변형 허용) | 가능 |
| `kogl-type-2` | 공공누리 제2유형 (상업적 이용 금지) | 조건부 — §4 |
| `kogl-type-3` | 공공누리 제3유형 (변형 금지) | 조건부 — §4 |
| `nikl-modu-approved` | 국립국어원 모두의 말뭉치, 승인받은 건 | 조건부 — §4 |
| `aihub-approved` | AI Hub, 승인받은 건 | 조건부 — §4 |
| `kogl-type-4` | 공공누리 제4유형 (상업 금지 + 변형 금지) | 사용하지 않음 |
| `mit`, `apache-2.0`, `bsd-3-clause` | 허용적 코드 라이선스. 고지·귀속 의무는 유지된다 | 가능 |

새 식별자가 필요하면 이 표에 먼저 추가하고, 승인 문서 번호·확인일을 §6에 적은 뒤 사용한다. **`unknown`, `web`, `crawled` 같은 값은 쓰지 않는다.** 출처 추적이 불가능한 데이터는 이 프로젝트의 필수 필드 정책과 맞지 않는다.

## 2. 후보 출처 — 신청 없이 받을 수 있는 것

파이프라인을 가장 빨리 열 수 있는 쪽이다. 1차 파일럿은 여기서 시작하기를 권한다.

| 출처 | 분야 | 예상 라이선스 | 확인해야 할 것 |
|---|---|---|---|
| 한국어 위키백과 덤프 (`dumps.wikimedia.org`) | `korean_general` | `cc-by-sa-4.0` | 본문과 인용·이미지 설명의 라이선스가 다를 수 있음. 위키 문법 제거 품질. 동일조건변경허락이 모델 가중치 공개 조건에 미치는 영향 |
| 위키문헌 / 위키낱말사전 | `korean_general` | 항목별 상이 | 자매 프로젝트는 라이선스가 갈린다. 한 덩어리로 취급하지 말 것 |
| 공공데이터포털 `data.go.kr` | `korean_general`, `traffic` | `kogl-type-1`~`4` | **데이터셋별로 유형이 다르다.** 제1유형만 골라 쓰면 가장 단순 |
| 국가법령정보센터 법령 본문 | `korean_general`, `traffic` | 공공누리 계열 | 도로교통법 등 교통 법령은 특화 분야에 직접 쓸 수 있음 |
| 우리가 직접 작성한 교통 예시 | `traffic` | `own-work` | 평가 문항과 같은 템플릿을 단어만 바꿔 대량 생성하지 말 것 ([기획 §5.4](project-plan.md)) |
| The Stack v2 (BigCode) | `code` | 원본 저장소별 허용적 라이선스 | 허용적 라이선스·무라이선스만 수집한 데이터셋이지만, **이용 시 원본 각 라이선스를 그대로 따라야 하고 귀속 조항도 유지된다.** 문서별 `license`를 원본 값으로 채울 수 있는지 확인 |

## 3. 후보 출처 — 신청·승인이 필요한 것

한국어 규모를 실제로 확보하려면 이쪽이 필요하다. **승인에 시간이 걸리므로 지금 신청해 두는 것이 좋다.**

| 출처 | 규모 | 확인해야 할 것 |
|---|---|---|
| 국립국어원 모두의 말뭉치 `corpus.korean.go.kr` | 한국어 최대 규모 공개 말뭉치군 | 계정·신청·승인 절차, 이용 목적 제한, **재배포 금지 여부**, 학습 결과물 공개 가능 범위 |
| AI Hub `aihub.or.kr` (NIA) | 분야별 대규모 데이터셋 | 공개 이용정책상 **승인 없는 열람·제공·양도·대여·판매가 금지**되고 용도가 AI 학습 모델 훈련으로 한정된다(2026-09-18 확인, §6.1). 데이터셋별 추가 약관, 상업 활용 시 별도 협의 필요 여부 |

재배포 금지 조건은 **원문 재배포**를 막는 것이고 학습 가중치 공개와는 별개일 수 있다. 다만 이 구분은 약관 문구에 따라 달라지므로 임의로 판단하지 말고 조항을 확인한다.

**협업 방식에 직접 영향을 준다.** AI Hub처럼 재배포가 금지된 데이터는 공동 작업자에게 파일로 전달할 수 없고 **각자 신청·승인받아야 한다.** 따라서 두 사람이 맞춰야 하는 것은 데이터 파일이 아니라 수집·정제 스크립트와 `manifest.json`의 hash다. 같은 스크립트로 각자 만든 결과가 같은 hash를 내는지로 동일성을 확인한다. 환경 차이는 [환경 문서](environments.md)를 함께 본다.

## 4. 주의가 필요한 출처

| 출처 | 문제 |
|---|---|
| 나무위키 | **CC BY-NC-SA 2.0 KR** (2026-09-18 확인). NC 때문에 상업적 전환이 막히고, 동일조건변경허락이라 **위키백과의 CC BY-SA 4.0과 호환되지 않는다** — 두 출처를 한 모델에 섞으면 산출물에 적용할 단일 조건을 정할 수 없다. 내용 신뢰성·문체 편향도 별도 문제 |
| 웹 크롤 코퍼스 (OSCAR, mC4, CulturaX 등 한국어 부분) | 배포자의 라이선스와 **원문 저작권이 다르다.** 문서별 `license`를 특정할 수 없어 필수 필드 정책과 충돌. `prepare.py`가 `license_not_allowed`로 전량 거절하게 된다 |
| 뉴스 기사 | 대부분 언론사 저작권. 접근 가능성과 이용 권리는 다른 문제 |
| 도서·논문 본문 | 별도 허락 없이 사용하지 않음 |
| `kogl-type-2` (상업 금지) | 연구 단계에서는 가능하나 상업 전환 시 재학습이 필요해진다. 혼합하면 **전체 모델이 제약을 물려받는다** |
| `kogl-type-3` (변형 금지) | 토큰화·정제가 '변형'에 해당하는지 판단이 필요. 불확실하면 제외 |

**권고: 1차 학습은 제약이 가장 약한 것끼리만 섞는다.** `kogl-type-2`/`type-3`를 한 건이라도 넣으면 모델 전체의 이용 조건이 그 제약으로 내려간다. 라이선스가 다른 데이터는 섞기 전에 결과물 공개 조건을 먼저 정해야 한다.

## 5. 평가 오염 방지 — 학습에서 격리할 것

아래는 **평가용이므로 학습 데이터에 절대 들어가면 안 된다.** 들어가면 평가 점수가 무의미해진다.

| 평가셋 | 용도 |
|---|---|
| KorQuAD 1.0 / 2.0 | 한국어 기계독해. **CC BY-ND 2.0 KR**(변경금지)로 알려져 있어 학습 사용 자체가 부적절 |
| KLUE | 한국어 이해 벤치마크. **CC BY-SA 4.0**이라 라이선스상으로는 사용 가능하지만, **오염 때문에** 학습에서 제외한다 |
| KoBEST | 한국어 zero/few-shot 평가 ([논문 정리](papers/README.md)에서 평가 기준으로 언급) |

격리 방법:

1. 평가셋을 `prepare.py`의 입력 JSONL에 **넣지 않는다.** 이게 1차 방어선이다.
2. 위키백과처럼 평가셋의 원문일 수 있는 코퍼스를 쓸 때는, 평가 문항의 지문과 학습 문서 간 중복을 별도로 검사한다. `prepare.py`의 MinHash 중복 그룹화는 **같은 입력 안에서만** 동작하므로 외부 평가셋과의 오염은 잡지 못한다.
3. `data_pipeline`의 `test` split은 최종 평가까지 열지 않는다. 토크나이저 선택도 `validation`만 쓴다 ([준비 문서 §2](data-readiness.md)).

KorQuAD는 변경금지(ND) 계열 라이선스로 알려져 있어 학습 사용 자체가 부적절하다. 평가 목적으로만 쓴다.

### 6.2 다운로드 기록표 (작성해야 함)

데이터를 실제로 받을 때마다 아래 표를 채운다. 이 표가 비어 있는 출처는 파이프라인에 넣지 않는다.

| 출처명 | `source` 값 | `license` 식별자 | 약관 URL | 확인일 | 확인자 | 승인번호 | 재배포 | 상업 이용 | 변형 |
|---|---|---|---|---|---|---|---|---|---|
| 한국어 위키백과 | `kowiki-20260901` | `cc-by-sa-4.0` | | **미기재** | **미기재** | 해당없음 | | | |
| | | | | | | | | | |

**위키백과 행은 아직 미완성이다.** 2026-09-18 [파일럿](../experiments/pilot-kowiki-2026-09-18/README.md)에서 `allowed_licenses`를 `["cc-by-sa-4.0"]`로 설정하고 이 출처로 파이프라인을 완주했으나, 근거는 위키백과 본문의 널리 알려진 라이선스이며 **사람이 약관을 확인한 기록이 아니다.** 확인일·확인자와 재배포/상업/변형 가부를 채워야 한다.

같이 정해야 할 것: 동일조건변경허락(SA)이 **학습 가중치 공개 조건**에 미치는 영향. 파일럿은 연구용 내부 실행이라 이 판단을 미뤘다.

## 7. 원문 레코드 변환 규칙

`prepare.py`가 받는 형식이다. 필수 필드는 `id`, `source`, `license`, `domain`, `text`이며 하나라도 없으면 `missing_provenance`로 거절된다.

```json
{"id":"kowiki-20260901-000001","source":"kowiki-20260901","license":"cc-by-sa-4.0","domain":"korean_general","text":"문서 내용\n다음 문단","group_id":"kowiki-20260901:12345","content_type":"text"}
```

| 필드 | 규칙 |
|---|---|
| `id` | 전역 고유. `<source>-<순번>` 권장 |
| `source` | **덤프 날짜·버전을 포함한다.** 같은 위키의 다른 시점을 구분해야 재현이 된다 |
| `license` | §1 어휘만 사용 |
| `domain` | 아래 어휘만 사용 |
| `group_id` | 선택. **반드시 `<source>:` 접두사를 붙인다.** 다른 출처의 그룹 ID와 충돌하면 무관한 문서가 한 그룹으로 병합되어 split이 오염된다 ([준비 문서 §1](data-readiness.md)) |
| `content_type` | `text` 또는 `html`. `domain=code`에 `html`을 쓰면 `prepare.py`가 에러로 거절한다 |

`domain` 어휘 (평가·혼합 비율 집계 단위):

| 값 | 내용 |
|---|---|
| `korean_general` | 한국어 일반 문서 |
| `english` | 영어·한영 혼합 |
| `code` | 소스 코드. HTML 제거 경로를 적용하지 않음 |
| `traffic` | 교통 특화 |

`group_id`를 쓸 곳: 같은 원문에서 파생한 문서(문서 분할, 번역쌍, 같은 시리즈), 같은 교차로·시간대의 교통 기록. 기획 문서는 시간 변화가 중요한 교통 데이터를 **시간·교차로·시나리오 그룹 기준으로 별도 보류**하라고 정하고 있다 ([기획 §5.3](project-plan.md)).

## 8. 결정해야 할 항목

코드가 대신 정할 수 없고 **프로젝트 소유자가 답해야 하는 것**이다.

| 항목 | 현재 상태 | 영향 |
|---|---|---|
| 사용할 출처 목록 | 미정 | `allowed_licenses` 확정, 파이프라인 실행 가능 여부 |
| 결과물 공개 범위 | 미정 (기획은 내부 실험 우선 가정) | 상업 금지·동일조건변경허락 데이터를 섞을 수 있는지 결정 |
| 분야 혼합 비율 | 기획 가설: 한국어 80% / 영어·혼합 10% / 수학·코드 10% | 실제 확보량에 맞춰 재산정. 비율을 억지로 맞추지 말고 실제 구성을 기록 |
| 총 토큰 예산 | 미정 | `scripts/plan_budget.py`로 계산. 자기 환경 실측 처리량 필요 ([환경 문서](environments.md)) |
| 교통 데이터 확보 경로 | 미정 | 특화 단계(LoRA/DoRA SFT) 진입 가능 시점 |
